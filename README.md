# Проєкт 1: Захищений канал телеметрії з обмеженою пропускною здатністю

Система призначена для передавання бортової телеметрії на наземну станцію через вузький канал зв'язку з пачковими втратами та обмеженим бюджетом часу. Проєкт реалізовано мовою C# на платформі .NET 8 із підключенням еталонної моделі каналу на Python.

## 2. Архітектура та структура проєкту

### Організація репозиторію

* `src/Core/` - основна бібліотека системи, структурована за модулями:
  * `Prediction` - вилучення часових ознак із вікна історії, багатошаровий перцептрон, потоковий класифікатор, тренувальний модуль і мажоритарний класифікатор.
  * `Compression` - канонічний кодер Гаффмана, режим без стиснення, бітовий запис і читання, таблиця довжин кодів.
  * `Packing` - точний алгоритм динамічного програмування для задачі про рюкзак 0/1, жадібний алгоритм та послідовний пакувальник.
  * `Scheduling` - пріоритетний планувальник черги відправлення пакетів за питомою цінністю та послідовна черга.
  * `Security` - виведення ключів PBKDF2-HMAC-SHA256, шифрування AES-256-CTR, автентифікація HMAC-SHA256 і сервіс захисту.
  * `Optimization` - генетичний алгоритм налаштування параметрів системи та алгоритм випадкового пошуку.
  * Корінь `Core` - моделі телеметрії та пакетів, конфігурація `TeamConfig`, читач `TelemetryReader`, приймач `TelemetryReceiver`, міст каналу `PythonChannel`, метрика якості `QualityMetric` і диспетчер пайплайну `SessionRunner`.
* `src/Cli/` - консольний додаток для навчання класифікатора, запуску сценаріїв каналу, оптимізації та генерації таблиць звіту.
* `tests/Tests/` - набір модульних, інтеграційних, безпекових і приймальних тестів xUnit.
* `data/` - конфігурація `team_config.json`, модель каналу `channel.py`, навчальна, валідаційна і сесійна вибірки, а також папка `reference/` з еталонними пакетами.
* `results/` - згенеровані таблиці експериментів, метрики перцептрона і журнали еволюції.
* `docs/` - специфікації формату й каналу та супровідна документація.

## 3. Інструкція із запуску та відтворення результатів

Для роботи системи потрібні встановлений .NET 8 SDK та Python 3 у системному шляху для запуску еталонної моделі каналу. Усі команди виконуються з кореневої теки репозиторію. Також до папки `data/` треба вкласти всі необхідні файли для роботи програми: `session.csv`, `train.csv`, `valid.csv`, `channel.py`, `team_config.json`

Перевірка збирання:
```bash
dotnet build -warnaserror
```

Запуск усіх модульних, безпекових, приймальних та еталонних тестів:
```bash
dotnet test
```

Запуск повного циклу навчання класифікатора, прогонів каналу, аналізу впливу блоків та генетичного алгоритму:
```bash
dotnet run --project src/Cli
```

або якщо вже відкритий slnx:
```bash
dotnet run
```

Після запуску в папці `results/` зберігаються актуальні таблиці `table1_dp_vs_greedy.csv`, `table2_ablation_blocks.csv`, `table3_crypto_order.csv`, `table4_loss_behavior.csv`, `ga_evolution.csv`, `random_search_history.csv`, `classifier_metrics.json`, `confusion_matrix.csv` та зведений звіт `full_pipeline_report.txt`.

## 6. Очікувані ризики та шляхи їх уникнення

* **Циклічна залежність ваг у задачі пакування.** Вага кадру після стиснення залежить від таблиці кодів Гаффмана, а сама таблиця залежить від того, які саме кадри обрано в пакет.  
  *План дій:* будувати одну таблицю Гаффмана для всього вікна кандидатів до запуску рюкзака, рахувати ваги кадрів за цією таблицею і кодувати обрані кадри нею самою.

* **Розростання таблиці Гаффмана на різнорідних кадрах.** При накопиченні кадрів із великою кількістю різних байтів таблиця може зайняти майже весь 512-байтний пакет, через що корисна місткість $W$ стане нульовою або від'ємною.  
  *План дій:* обмежити вікно кандидатів 64 кадрами та передбачити автоматичне перемикання пакета на передавання сирих байтів без стиснення, якщо таблиця не вміщається або не дає виграшу.

* **Погіршення швидкодії та помилки конфігурації криптографії.** Повторне виконання 100 000 ітерацій PBKDF2 на кожному пакеті перевантажить процесор і спотворить показник швидкодії $T$, а повторення вектора `nonce` у режимі CTR зруйнує стійкість шифру.  
  *План дій:* обчислювати й кешувати сеансові ключі один раз на сеанс, генерувати унікальний `nonce` для кожного пакета з прив'язкою до порядкового номера і перевіряти HMAC у постійний час до дешифрування.

* **Нестійкість навчання багатошарового перцептрона.** Одна випадкова ініціалізація ваг може призвести до поганого локального мінімуму та згортання прогнозів до мажоритарного класу, а використання лише полів одного кадру не дозволить розпізнати перехідний режим.  
  *План дій:* формувати ознаки на основі ковзного вікна історії, ділити навчальну вибірку у співвідношенні 80/20 і повторювати навчання щонайменше з трьох різних початкових ініціалізацій із відбором моделі за найкращим macro-F1 на валідації.

* **Висока втрата критичних кадрів в аварійному сценарії.** Через вузьку смугу пропускання, пачкові втрати та жорсткий бюджет часу передавання частина пакетів не встигає потрапити в канал і відкидається.  
  *План дій:* використовувати пріоритетний планувальник черги відправлення, який сортує сформовані пакети за питомою цінністю, щоб пакети з критичними кадрами відправлялися першими.
```
